# P2-D-1 驗收｜帳號生命週期與內容保存治理

日期：2026-09-26  
版本：0.3.0  
結論：**P2-D-1 本機切片通過；P2-B／P2-C 既有流程維持通過。尚未開始 P2-D-2 設定版本與 P2-D-3 備份／隔離還原。**

## 1. 已完成能力

- 管理者可停用／重新啟用帳號，不能停用目前登入的自己。
- 管理者可重設密碼；密碼雜湊更新後，該帳號既有工作階段立即失效。
- 管理者可編輯角色、設備範圍與 Profile；權限版本遞增並撤銷既有工作階段。
- 目前管理者不能移除自己的 `admin`，避免單一步驟自我鎖死。
- 建立提案時必須在 1 日與 7 日保存期中選擇；未指定的舊客戶端向後相容採 7 日。
- 到期清除提案參數、審核理由、工單問題／時段／風險及相關執行 Trace 摘要。
- 清除後保留識別碼、時間、狀態、雜湊及稽核事件，讓刪除本身仍可驗證。
- 清除後後端以 `CONTENT_EXPIRED` 阻擋送審、審核、執行及結果查回，不依賴前端隱藏按鈕。
- 正式本機資料庫由 `p2c-1` 相容升級為 `p2d1-1`；既有表不重建、環境指紋不變。

## 2. 可操作介面

- 提案表單可選 1 日或 7 日，並在送出前解釋會清除與保留的資料。
- 提案卡顯示保存天數、到期時間或「已清除」，清除後不顯示原問題摘要。
- 帳號卡可編輯角色、設備、Profile、停用／啟用及重設密碼。
- 自身停用按鈕在介面停用，後端仍獨立拒絕繞過 UI 的請求。

## 4. 資料邊界

- 測試仍使用獨立 `automated_test` 資料庫。
- 正式本機資料庫沒有建立展示帳號或測試提案。
- 保存清除是資料最小化，不是完整資料庫備份或災難復原。
- 密碼重設 Trace 只記目標帳號識別與撤銷結果，不記密碼或雜湊。
