# P2-D-2 驗收｜Profile 設定版本治理

日期：2026-09-27  
版本：0.4.0  
結論：**P2-D-2 本機切片通過；P2-B、P2-C 與 P2-D-1 回歸維持通過。尚未開始 P2-D-3 正式 migration ledger、備份與隔離還原。**

## 1. 已完成能力

- 每個 Profile 具有不可覆寫的版本快照、版本號、政策版本、來源雜湊、狀態與建立者。
- 生命週期實作為 `draft → validated → previewed → submitted → approved → active → superseded`；進行中的候選也可由 admin 明確取消，保留歷史後再建立下一版。
- 草稿只接受白名單欄位與已知設備；拒絕未知欄位、URL 型外部設定及改寫工具安全底線。
- 驗證後才能產生差異預覽；預覽後才能送審，不能跳步呼叫 API。
- `reviewer` 必須在該 Profile 範圍內且不可為提出者；`admin` 不會自動取得 reviewer。
- 只有已獨立核准且基礎版本未漂移的候選可以套用。
- 套用會實際改變顯示名稱、範圍標籤、品牌色、術語、設備範圍、核准人數、必填欄位與預設保存期限。
- 套用後的新提案綁定新 Profile／policy 版本；舊提案保留原快照並標為失效，不重寫歷史。
- 還原從已啟用過的版本建立下一個新草稿，仍須重新驗證、預覽、核准與套用。
- Profile seed 改為只在首次建立時寫入；重新啟動不再覆寫 active 客製設定或重新擴張設備關聯。

## 2. 可操作介面

- admin 可選 Profile、調整客製欄位、建立草稿並依序驗證、預覽、送審、取消候選、套用或建立還原草稿。
- reviewer 只看到授權範圍內的版本，可填寫理由後核准或退回。
- 每張版本卡顯示狀態、版本、政策版本、來源基線、四項摘要、逐欄 before／after 及核准歷史。
- 介面以繁體中文呈現狀態與欄位；技術識別碼保留原值。
