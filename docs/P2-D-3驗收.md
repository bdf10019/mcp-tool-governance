# P2-D-3 驗收｜可驗證遷移、去內容備份與唯讀隔離還原

日期：2026-09-27

版本：0.5.0
結論：**P2-D-3 本機切片通過；P2-B、P2-C、P2-D-1 與 P2-D-2 回歸維持通過。下一階段固定為 P2-E 獨立離線介紹網站。**

## 1. Migration ledger

- 固定四段 registry：`001-p2c-core`、`002-p2d1-retention`、`003-p2d2-profile-versions`、`004-p2d3-backup-restore`。
- 每段保存 from／to schema、合約與實作指紋形成的 SHA-256、running／applied／failed、開始／完成時間及不含 payload 的錯誤碼。
- 已套用 checksum 不符、未知已套用 migration 都會拒絕初始化，不會默默覆寫。
- 失敗 migration 會留下 `failed／MIGRATION_FAILED`，再次執行仍須使用相同 checksum。
- 舊 `p2c-1`、`p2d1-1`、`p2d2-1` marker fixture 均可依序升至 `p2d3-1`；連續初始化不重複 seed 或改寫 ledger。

## 2. 去內容備份

- admin 先看包含／排除清單、資料列數與身分統計，再輸入「建立去內容備份」。
- 備份使用白名單投影，只保留 schema／migration、Profile 安全快照、seed manifest、去識別角色統計，以及提案／核准／執行／工單的關係與狀態摘要。
- 使用者、提案、執行與工單 ID 以每份備份專用雜湊參照取代；不輸出 username。
- 排除密碼／salt、Session、CSRF、auth context、原始工具輸入輸出、Trace summary、提案參數、審核理由、工單內文、冪等鍵與 outbox payload。
- 暫存檔完成 flush／fsync 後再原子取代，產出 payload SHA-256、檔案 SHA-256、大小、manifest 與排除清單。
- 檔案缺失、符號連結、路徑越界或檔案 SHA 不符會拒絕下載與還原。

## 3. 唯讀隔離還原

- 只接受本產品已登錄、檔案 SHA 與 payload SHA 均正確、schema 相容且 `authority_included=false` 的備份。
- 還原目標由後端建立新 UUID；API 不接受使用者指定路徑，來源資料庫不會被覆寫。
- 測試環境把備份與還原放在該次測試資料庫的獨立暫存根；其他來源環境無法看見其收據。
- active Profile 只成為 `pending_validation_readonly` 候選；業務關係全部標為 `restored_readonly`。
- 還原資料庫沒有 users、sessions、auth_contexts、approvals、executions 或產品工具入口。
- 每張收據固定揭露：0 Sessions、0 auth contexts、0 active approvals、0 auto replay、0 MCP calls，並驗證來源邏輯內容雜湊未改變。

## 4. 可操作介面

- 新增「備份與還原」治理頁，只有 admin 看得到入口，後端仍會再次強制角色。
- 可查看目前 schema、四段 ledger、短 checksum、套用狀態與漂移結果。
- 備份預覽以綠／紅雙欄呈現包含與排除內容，並顯示各資料類別列數。
- 可建立、下載已驗證備份，選擇備份後建立隔離還原。
- 還原收據以五個零權威指標、來源內容不變、待驗證設定與唯讀關係數呈現。
- 桌機與 390px 手機版均以真實後端流程完成，不使用固定展示結果。

## 7. 限制與下一步

1. 去內容備份是治理／稽核投影，不是能重建完整業務內容的災難復原檔。
2. 尚無雲端儲存、排程、跨機復原、加密金鑰代管或備份保留排程。
3. 唯讀保證由資料模型、獨立路徑、沒有產品權威表與後端入口共同成立；不宣稱作業系統檔案權限可取代應用層安全。
4. P2-E 介紹網站尚未開始；不得把本控制台當成已完成的公開作品網站。
